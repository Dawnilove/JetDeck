# JetDeck 5.6.0

> **플러그인 모음 2단계** 업데이트예요. 모음에서 받은 팩이 **철회되면 앱이 자동으로 꺼요.** 모음에 **업데이트 있음** 표시와 **신고** 버튼이 생겼고, 누구나 **Pull Request로 팩을 제출**할 수 있어요(자동 검사 + 관리자 심사). 기기에는 아무것도 설치하지 않아요.

5.5.x를 쓰고 있다면 앱을 켤 때 **자동으로 받아서** 화면 위쪽에 알려 줘요. **다시 시작해서 업데이트**를 누르면 끝.

## ✨ 새 기능

- **철회된 팩 자동 끄기** — 관리자가 모음에서 내린(철회한) 팩을 이미 설치했고 켜 두었다면 앱이 **자동으로 꺼요.** 파일은 지우지 않고, 플러그인 관리의 팩 줄에 빨간 줄로 이유를 보여 줘요. 다시 켜려면 "철회된 팩이에요. 그래도 켤까요?" 확인을 한 번 더 거쳐요. 알고 켜 둔 팩은 다음 확인에서 또 끄지 않아요. 끄면 OS 알림도 떠요.
  - 대상은 **모음에서 받은 파일 그대로인 팩**뿐이에요. 직접 설치했거나 파일을 바꾼 팩은 건드리지 않아요.
- **하루 1번 철회 확인** — 모음 탭을 열 때, 그리고 **모음에서 받은 팩이 하나라도 있는 사용자만** 앱을 켠 뒤 하루 1번 모음에 접속해 철회를 확인해요(안내에 동의했을 때만). **모음 탭 아래의 "앱을 켤 때 하루 1번 철회 확인" 체크를 끄면** 앱을 켤 때 접속하지 않아요. 모음에서 받은 팩이 없으면 앱을 켤 때 아무 데도 접속하지 않아요(5.5.0과 같아요).
- **업데이트 있음** — 설치한 팩의 새 버전이 모음에 있으면 목록에 표시해요. **자동으로 설치하지 않아요.** 내용 보기에서 "업데이트예요" 안내와 함께 **바뀐 명령**이 강조돼요. 새 파일은 지문이 달라서 다시 허용해야 켜져요.
- **신고 버튼** — 목록 카드와 내용 보기 창의 **신고**가 GitHub 이슈 양식(`pack-report`)을 열고, 팩 id·버전·파일 지문 앞 8자리를 채워 줘요. 공개 이슈라 개인정보를 적지 말라는 안내가 있어요. 팩이 안전 검사를 **우회**한다면 비공개 취약점 제보 링크를 써 주세요. **신고만으로 앱이 팩을 끄지는 않아요**(철회는 관리자만 해요).
- **커뮤니티 제출** — 누구나 PR로 팩 파일 하나를 올릴 수 있어요(`docs/packs/files/<id>/<버전>/<id>.jdpack.json`, 양식 `?template=pack-submission.md`).
  - **자동 검사(`Pack check`)**: 앱과 같은 검증기로 읽기만 해요. 팩을 실행하지 않아요. 공식·예약 id, 공식·기존 팩과 **한 글자 차이** id, 앱 계산보다 **낮게 적은** 위험도, 128KB 초과, 이미 올린 파일 수정, 제어·보이지 않는 글자, `license`·`author`·`desc` 누락, 위험 항목에 이유가 없는 PR을 막아요. 결과와 명령 전문은 실행 요약에 나와요.
  - **사람 심사**: 관리자가 모든 명령을 읽어요([심사 기준](https://github.com/Dawnilove/JetDeck/blob/main/docs/plugins/review.md)). `CODEOWNERS`로 `docs/packs/`는 관리자 승인이 필요해요.
  - **합쳐도 모음에는 바로 안 보여요.** 관리자가 서명한 새 목록을 게시해야 보여요.
- **문서** — [심사 기준](https://github.com/Dawnilove/JetDeck/blob/main/docs/plugins/review.md), [게시·신고·철회 절차](https://github.com/Dawnilove/JetDeck/blob/main/docs/plugins/publish.md), 보안 문서, `CONTRIBUTING.md`의 "모음에 팩 올리기", `SECURITY.md`의 모음 팩 제보.
- **수정** — 모음 탭 아래 "모음 동의 끄기" 버튼이 5.5.0에서 글자가 잘려 보이던 문제.

## ⚠ 바뀐 점 — 꼭 읽어 주세요

- **모음에서 받은 팩이 있고 모음 안내에 동의했다면, 앱을 켠 뒤 하루 1번 모음에 접속해요.** 보내는 것은 5.5.0과 같아요(요청 자체: IP 주소·시각·앱 이름과 버전). 기기 정보·설치한 팩 목록·검색어는 보내지 않아요. 끄는 방법은 위와 같아요.
- **철회가 닿는 데 최대 하루쯤 걸려요.** 모음 탭을 열면 바로 확인해요. 앱을 안 켜는 동안에는 받을 수 없어요.
- **"검토됨"은 안전 보증이 아니에요.** 관리자가 명령을 읽어 봤다는 뜻이에요. 자동 검사의 초록 표시는 "파일 모양이 맞다"는 뜻일 뿐이에요.
- 5.5.x 이하 앱은 자동으로 끄지 못해요. 철회는 같은 목록으로 전달되니 업데이트해 주세요.

## 확인한 범위

확인한 것:

- 자동 시험 436개, 타입 검사, 영어 사전 검사(누락 0), 빌드 통과. 철회 처리(켜진 팩만 끔·직접 설치한 팩 무시·버전/지문 불일치·두 번 실행·알고 켠 팩·새 버전에는 기록이 안 붙음), 하루 1번 확인 조건 표, 나쁜 팩 샘플 14종(낮게 적은 위험도, 공식 id 사칭, 비슷한 id, 큰 파일, 기존 파일 수정·삭제, 제어 문자, 필수 항목 누락, 경로 모양 등)이 모두 실패하는지, 실제 공개 팩 3개는 통과하는지를 시험으로 고정했어요.
- 실제 앱(빌드본)을 **로컬 가짜 서버**로 움직여 확인: 철회 목록을 받으면 켜진 팩이 자동으로 꺼지고 이유가 기록됨 · 확인 없이 다시 켜기는 거부, 확인하면 켜지고 다음 확인에서 다시 끄지 않음 · 업데이트 표시와 바뀐 명령 개수 · **앱을 켠 뒤 10초쯤 지나 모음에 접속**해 철회된 팩을 끔 · 같은 날 다시 켜면 접속하지 않음 · 스위치를 끄면 접속하지 않음 · 받은 팩이 없으면 접속하지 않음 · 목록에 없는 팩 신고는 거부. 화면(철회 줄, 업데이트 칩, 신고 버튼, 스위치)은 스크린샷으로 봤어요.
- 제출 검사 스크립트를 실제 git 저장소(임시 작업 폴더)에서 돌려 좋은 PR은 통과, 수정·잘못된 팩은 실패하는 것을 확인했어요.

**확인하지 못한 것**:

- **GitHub Actions에서 `Pack check`가 실제로 도는 것**과 요약 표시, `pack-report` 이슈 양식에 id·버전이 미리 채워지는지(필드 이름이 맞는지), PR 양식 선택 주소. 첫 PR이 오면 확인해야 해요.
- **`CODEOWNERS`가 효력을 내려면** 저장소 설정에서 "Require review from Code Owners"를 켜야 해요(아직 안 켬).
- 신고 버튼이 **기본 브라우저를 여는 것**(목록에 없는 팩의 거부만 확인), **OS 알림이 실제로 뜨는 것**, 영어 화면의 눈 확인, 밝은 테마, 내용 보기 창의 업데이트 강조 화면(문구·개수는 확인), 설치판 업데이트 알림.
- 한 번 철회됐다가 목록에서 철회가 풀린 경우(철회 기록은 남아 있어요: 직접 켜면 돼요).
