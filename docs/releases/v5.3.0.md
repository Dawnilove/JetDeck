# JetDeck 5.3.0

> **탐색기 배지 + 보안 수정** 업데이트예요. 폴더를 열면 파일·폴더 옆에 작은 표시(M·U 같은 Git 상태 등)가 붙고, 팩 항목과 탐색기가 실행하는 `git` 명령의 보안 문제를 고쳤어요. 내 PC에서 코드는 여전히 실행되지 않고, 기기에는 아무것도 설치하지 않아요.

5.2.0을 쓰고 있다면 앱을 켤 때 **자동으로 받아서** 화면 위쪽에 알려 줘요. **다시 시작해서 업데이트**를 누르면 끝.

## 🔒 보안 수정 — 업데이트를 권해요

**무엇이 문제였나요.** 아래 두 곳이 실행하는 `git` 명령이, **믿을 수 없는 저장소**(받은 압축 파일, 남의 저장소를 clone한 폴더)가 든 **연결한 기기(Device)** 에서, 그 저장소 안에 적힌 설정이 시키는 프로그램을 실행할 수 있었어요.

| 어디서 | 영향받는 버전 | 언제 |
|---|---|---|
| **탐색기의 Git 표시** | 4.1.0 ~ 5.2.0 | 그런 폴더를 탐색기에서 **열기만** 해도 |
| **팩 항목**(플러그인)이 실행하는 `git` 명령 | 5.0.0 ~ 5.2.0 | 켜 둔 팩의 `git` 항목을 실행하거나 미리보기·실시간·그래프로 돌릴 때. 앱이 읽기로 증명한 명령이라 확인창 없이 실행됐어요 |

* **어디서 실행되나요.** 연결한 **기기에서, 연결한 SSH 계정의 권한으로** 실행돼요. **내 PC에서는 실행되지 않아요.**
* **조건.** ① 기기에 그런 저장소가 있어야 하고 ② 위 두 곳이 그 폴더에서 `git`을 실행해야 해요. 앱을 켜는 것만으로 저절로 시작되지는 않고, 공격자가 먼 곳에서 임의로 시작할 수도 없어요.
* **공식 팩**에는 `git` 항목이 없어요. 직접 설치한 팩이나 예제 팩의 `git` 항목이 해당돼요.

**5.3.0에서 고친 것.** `git`을 실행하기 전에 저장소 자신의 설정을 검사하고, **프로그램을 실행할 수 있는 설정이 있으면 `git`을 실행하지 않아요**(탐색기에는 ⚠ 표시와 이유, 팩 항목에는 "이 저장소의 설정이 위험해서 실행하지 않았어요"). 훅·서명 확인 프로그램·페이저도 꺼요. 이 보호는 탐색기와 **`git`을 쓰는 모든 팩 항목**(버튼·미리보기·실시간 보기·그래프·`from` 선택 목록)에 적용돼요. 앱이 `/usr/bin/git`처럼 경로로 부른 `git`이나 `xargs`·`env` 같은 다른 프로그램을 거친 `git`은 이제 읽기로 인정하지 않고 먼저 물어요.

**권장.** 5.3.0으로 업데이트하세요. 업데이트 전에는 믿을 수 없는 출처의 저장소 폴더를 탐색기에서 열지 말고, `git`을 쓰는 팩 항목을 실행하지 마세요. 자세한 방어 방식은 [팩 보안 문서](https://github.com/Dawnilove/JetDeck/blob/main/docs/plugins/security.md)에 있어요.

한계: 저장소마다 설치한 Git LFS처럼 저장소 **로컬** 필터 설정이 있는 정상 저장소도 같은 이유로 거부돼요(안전한 쪽으로 실패, 배지·git 항목만 안 보여요).

## ✨ 새 기능

- **탐색기 배지** — 폴더를 열면 켜진 팩의 배지 명령이 그 폴더에 대해 **저절로** 실행돼요. 결과가 있는 파일·폴더 이름 옆에 **작은 표시**(1~2글자, 색은 앱이 정해요)가 붙고, 마우스를 올리면 설명이 떠요. 안에 표시가 있는 폴더에는 `●`, 기준 폴더(예: Git 저장소 최상위) 이름 옆에는 `tag`(예: 브랜치)가 보여요. 기준 폴더를 한 번 알아내면 그 안 하위 폴더에서는 다시 묻지 않고, 새로고침(↻)할 때만 다시 읽어요. 실시간 감시는 없어요.
- **끌 수 있어요** — 플러그인 관리의 **"탐색기 배지"** 스위치로 팩은 켜 둔 채 배지의 자동 실행만 멈출 수 있어요. `--safe-mode`에서는 외부 팩과 그 배지가 모두 꺼져요.
- **읽기 명령만** — 배지 명령은 **앱이 읽기 전용으로 증명한 것만** 쓸 수 있어요. 팩을 읽을 때 한 번, 실행 직전에 실제 폴더 이름을 채운 뒤 한 번 더 확인하고, 읽기가 아니면 말없이 건너뛰어요(예: `~/.ssh` 폴더). 같은 폴더는 `ttl`(3초 이상) 동안 다시 안 읽고, 연결당 한 번에 하나, 시간 제한 최대 15초, 연속 3번 시간 초과하면 그 접속 동안 멈춰요.
- **새 공식 팩 "개발 도구 (베타)"** — **Git 상태 배지**(M 수정·A 추가·D 삭제·U 새 파일·! 충돌, 브랜치 이름). **기본 꺼짐**이에요. 켜면 탐색기가 내장 Git 표시를 건너뛰어서 같은 표시가 두 번 나오거나 `git status`가 두 번 돌지 않아요. 끄면 내장 표시가 그대로 돌아와요. (내장 Git 표시는 지우지 않았어요.)
- **허용 창·플러그인 관리 창** — 머리말에 "배지 N", "자동으로 돌아가는 것" 구역에 **"폴더를 열 때"** 줄(명령 전문)과 `[읽기][폴더 열 때 자동]` 태그가 생겼어요.
- **팩 만드는 법** — [docs/plugins](https://github.com/Dawnilove/JetDeck/tree/main/docs/plugins)에 배지 절(형식·제한·끄는 법), 보안 문서의 "폴더를 열 때 저절로 실행되는 것" 절, JSON Schema, 예제 팩의 배지 예(`.py`·`.sh` 파일 표시)를 추가했어요. 배지를 쓰는 팩에는 `"minApp": "5.3.0"`을 적으세요.

## ⚠ 바뀐 점 — 꼭 읽어 주세요

- 위 보안 수정 때문에 **`git` 항목의 출력이 조금 달라졌어요**: `git status`는 서브모듈 안을 보여 주지 않고(`--ignore-submodules=all`), 사용자가 직접 `--ignore-submodules`·`--show-signature`·`--recurse-submodules` 같은 옵션을 적은 항목은 이제 읽기로 인정되지 않아 확인창이 떠요.
- 저장소 **로컬** 필터·textconv 설정이 있는 저장소에서는 `git` 항목과 배지가 거부돼요(위 한계).
- 5.2 앱이 `minApp` 5.3.0인 팩을 열면 팩 전체가 거부돼요. `minApp` 없이 `badges`를 쓴 팩은 5.2 앱에서 배지만 무시돼요(위험하지는 않아요). 5.0~5.2 팩은 그대로 동작해요.
- `root`를 적지 않은(`dir`) 배지는 **연 폴더만** 읽고, 하위 폴더를 열 때마다 다시 읽어요. Git처럼 `root: "line1"`인 배지만 기준 폴더 안을 한 번에 덮어요.

## 확인한 범위

확인한 것 (Jetson Orin Nano 1대, 읽기 명령과 임시 폴더만 사용, 시험 후 지움):

- 실제 앱 화면에서 **Git 상태 배지**: M·U·`●`·브랜치 태그, Git이 아닌 폴더는 표시 없음, **"탐색기 배지" 스위치를 실제로 눌러** 끄면 내장 Git 표시가 돌아오고 켜면 배지가 돌아옴, 예제 팩 배지(`.py`·`.sh`)와 동시에 켜진 상태, 허용 창의 "폴더를 열 때" 줄(외부 팩), `--safe-mode`에서 외부 팩 무시.
- **보안 수정**: 저장소 설정으로 프로그램을 실행하게 만든 시험 저장소를 탐색기에서 열었을 때 ⚠ 표시가 뜨고 **표식 파일이 생기지 않음**. 같은 시험을 팩 항목의 실행·미리보기·실시간 보기·그래프·`from` 목록 길에서도 진짜 `git`(2.43)으로 확인했어요(옛 보호에서는 표식이 생기는 것을 먼저 재현).
- 큰 저장소: 파일 6000개·변경 2000개 저장소에서 탐색기가 정상으로 표시했고, `git status` 명령 자체는 약 0.02초(따뜻한 상태)였어요.
- 자동 시험 328개, 타입 검사, 영어 사전 검사, 빌드 통과.

**확인하지 못한 것**:

- 큰 저장소를 **처음** 열 때의 표시까지 걸리는 정확한 시간(위는 명령 시간만 쟀어요), 느린 연결에서 시간 초과 3번 정지(자동 시험만), 분할 화면에서 두 탐색기가 동시에 묻는 경우(코드만).
- 영어 화면 전체(탐색기 툴팁·관리 창·허용 창은 일부 확인), 밝은 테마, 설치판 업데이트 알림.
- 다른 기기(Raspberry Pi 등)·다른 Git 버전, Git 2.15 미만(배지가 안 보일 수 있어요), Git LFS 저장소.
- 공격 시험은 우리가 떠올린 방법들이에요. 새로운 우회 방법을 찾으면 GitHub의 "Report a vulnerability"로 알려 주세요.
