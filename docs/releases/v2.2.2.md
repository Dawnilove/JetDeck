# JetDeck 2.2.2

> JetDeck을 **업데이트해도 Claude·Cursor 같은 AI와의 연결이 끊기지 않게** 했어요 (Windows).

2.2.1 이하를 쓰고 있다면 앱을 켤 때 **자동으로 받아서** 화면 위쪽에 알려 줘요. **다시 시작해서 업데이트**를 누르면 끝.

## 🛠 고친 점

- **업데이트하면 AI 연결이 끊기던 문제 (Windows)** — 업데이트를 설치하는 동안 설치 프로그램이 실행 중인 `JetDeck.exe`를 모두 종료하는데, AI가 쓰던 연결 프로그램(`JetDeck.exe --mcp`)도 같은 이름이라 같이 종료돼 AI 쪽 연결이 끊겼어요. 이제 AI가 실행하는 연결 프로그램을 Windows 기본 **PowerShell 스크립트**로 따로 만들어서(`~/.jetdeck/mcp-bridge.ps1`, JetDeck이 켜질 때마다 최신으로 갱신), 업데이트 설치에 종료되지 않아요. JetDeck이 잠깐 꺼져 있는 동안 도구를 부르면 다시 켜질 때까지 기다렸다가 이어서 처리해요. 연결 불도 JetDeck이 다시 켜지면 1초 안에 돌아와요.

## ⚠ 한 번만 다시 등록해 주세요

예전 방식(JetDeck.exe)으로 AI에 등록했다면 그대로도 동작하지만 업데이트 때는 계속 끊겨요. 연결 유지를 쓰려면 **MCP 연결 창**(연결 화면·작업 공간 위쪽의 **MCP** 버튼)에서 새로 보여 주는 설정을 한 번 다시 등록하세요.
- Claude Code: `claude mcp remove jetdeck` 후 창에 나온 `claude mcp add …` 명령 실행
- Claude Desktop·Cursor 등: 창에 나온 설정으로 기존 `jetdeck` 항목을 바꾸고 그 프로그램을 다시 켜기

> 이 개선은 Windows 전용이에요. Linux(AppImage)는 업데이트 설치가 연결 프로그램을 따로 종료하지 않아서 연결이 이어질 가능성이 높지만, 직접 확인하지는 못했어요. 끊기면 Claude Code는 `/mcp`로 다시 연결하세요. 가짜 AI 클라이언트로 연결·도구 호출·"JetDeck이 꺼졌다 켜지는 동안의 호출 대기"를 확인했고, 실제 Claude에서 업데이트 중 연결이 유지되는지는 이번 업데이트 뒤에 확인할 수 있어요. 안 되면 [이슈](https://github.com/Dawnilove/JetDeck/issues)로 알려 주세요.

## ⬇ 내려받기

| 파일 | 용도 |
|---|---|
| `JetDeck-Setup-2.2.2.exe` | **Windows 설치판 (추천)** — 자동 업데이트 |
| `JetDeck-2.2.2-portable.exe` | Windows 설치 없이 실행 |
| `JetDeck-2.2.2-x86_64.AppImage` | Linux x64 (자동 업데이트) |
| `JetDeck-2.2.2-arm64.AppImage` | Linux arm64 — Jetson 등 (자동 업데이트) |
