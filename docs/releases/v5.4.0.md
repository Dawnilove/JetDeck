# JetDeck 5.4.0

> **ROS2 launch·bag을 팩으로 옮겨 보는** 업데이트예요. 공식 팩 "ROS2 실시간·launch·bag (베타)"에 launch 실행, bag 재생·녹화가 생겼고, 팩 항목에 **정지 유예(`stopGrace`)** 를 적을 수 있어요. 내장 ROS2 화면은 그대로 있어서 나란히 써 볼 수 있어요. 기기에는 아무것도 설치하지 않아요.

5.3.0을 쓰고 있다면 앱을 켤 때 **자동으로 받아서** 화면 위쪽에 알려 줘요. **다시 시작해서 업데이트**를 누르면 끝.

## ✨ 새 기능

- **launch 실행 (팩)** — 플러그인 "ROS2 launch (베타)". 목록에서 launch 파일을 고르고 **시작**을 누르면 `ros2 launch`의 출력이 실시간 로그 카드로 나와요. 목록에는 홈 폴더 아래 파일(`site-packages`·`node_modules`·숨김 폴더는 건너뜀)과 설치된 ROS 패키지의 파일이 나와요. 멈추면 Ctrl-C를 보내고 **10초까지** 노드가 정리되기를 기다려요.
- **bag 재생 (팩)** — 플러그인 "ROS2 bag (베타)"의 "bag 재생". 홈 폴더 아래에서 찾은 bag을 고르고, 속도(0.5배·1배·2배)와 "끝나면 처음부터 반복"을 정해요. 출력은 로그 카드에 나오고, 멈추면 5초까지 기다려요.
- **bag 녹화 (팩)** — "bag 녹화 — 모든 토픽"과 "bag 녹화 — 토픽 하나". 내장 화면처럼 **터미널에 명령을 입력**해요. 멈출 때는 그 터미널에서 Ctrl+C를 눌러요.
- **기본 꺼짐·베타** — 이 팩은 플러그인 관리에서 켜야 보여요. 내장 ROS2 화면(토픽·노드·서비스·파라미터·bag·launch)은 **지우지 않았어요**. 두 화면을 나란히 써 보고 불편한 점을 알려 주세요.
- **정지 유예 `stopGrace`** — 팩 항목(`stream`)에 적으면, 멈출 때 Ctrl-C를 보낸 뒤 채널을 닫기까지 기다리는 시간이 늘어나요. 기본은 예전처럼 3초예요. 직접 설치하는 팩은 3~10초, 공식 팩은 3~30초까지 적을 수 있어요. 화면을 나가거나 연결이 끊기거나 앱을 닫을 때의 정리는 그대로이고, 앱을 닫을 때는 기다리지 않아요.
- **팩 만드는 법** — [docs/plugins](https://github.com/Dawnilove/JetDeck/tree/main/docs/plugins)에 `stopGrace` 절, 보안 문서의 정리 설명, JSON Schema, 예제 팩의 launch 예(`run-launch`)를 추가했어요. `stopGrace`를 쓰는 팩에는 `"minApp": "5.4.0"`을 적으세요.

## ⚠ 바뀐 점 — 꼭 읽어 주세요

- **launch와 bag 재생은 실행할 때마다 확인창이 떠요.** 앱이 읽기 전용으로 증명할 수 없는 명령이에요. launch 파일은 이 기기에서 그 파일에 적힌 코드를 실행하고, bag 재생은 메시지를 다시 발행해서 로봇이 움직일 수 있어요. 믿을 수 있는 파일만 실행하세요.
- **bag 정보(info)는 이 팩에 없어요.** 앱이 `ros2 bag info`를 읽기 전용으로 증명하지 못해서(읽기 목록은 이번에도 늘리지 않았어요), 팩에 넣으면 볼 때마다 확인창이 떠요. bag 정보는 내장 ROS2 화면의 bag 탭을 쓰세요.
- 팩의 launch는 **파일 하나를 골라 실행**해요(launch 인자 `이름:=값`은 아직 못 넣어요). 인자가 필요하면 내장 launch 탭에서 터미널로 실행하세요.
- 5.3 앱이 `minApp` 5.4.0인 팩을 열면 팩 전체가 거부돼요. `minApp` 없이 `stopGrace`를 쓴 팩은 5.3 앱에서 예전처럼 3초 뒤 멈춰요. 5.0~5.3 팩은 그대로 동작해요.

## 확인한 범위

확인한 것 (Jetson Orin Nano 1대, ROS2 Jazzy 데모 노드와 임시 파일만 사용, 시험 후 지움):

- **기기에 프로세스가 남지 않는지** — `ros2 launch`(talker·listener 데모), `ros2 bag play`, `ros2 bag record`를 앱과 같은 방식(pty 안의 `bash -ic`)으로 시작하고, ① Ctrl-C ② 채널 닫기 ③ 연결 종료 ④ 연결이 갑자기 끊김 뒤에 `pgrep`으로 확인했어요. 모두 **남은 프로세스 0개**. Ctrl-C 뒤 종료까지 0.3~0.8초였어요.
- **실제 앱에서** — 팩 켜기, launch 파일 목록과 bag 목록을 기기에서 읽기, 확인 없이 시작하면 **거부**, 파일 이름에 셸 글자(`x; touch …`)를 넣으면 거부(기기에 파일이 안 생김), 확인 토큰으로 launch 시작(기기에서 launch·talker·listener 3개 실행) → 멈춤 버튼 → 약 0.4초 만에 끝나고 **기기에 0개**, launch와 bag 재생을 **동시에** 돌린 상태에서 앱 프로세스를 **강제 종료**해도 **기기에 0개**. bag 녹화 입력 글자(`ros2 bag record -o 'jdbag' -a`)와 위험도(바꿈)도 확인했어요.
- 자동 시험 332개, 타입 검사, 영어 사전 검사(팩 글자쌍 누락 0), 빌드 통과. `ros2 launch`·`bag play`·`bag record`가 읽기가 아님을 시험으로 고정했어요.

**확인하지 못한 것**:

- **화면에서 직접 눌러 보기**: 확인창의 버튼, 새 플러그인 카드의 모양, 영어 화면, 밝은 테마는 눈으로 확인하지 못했어요 (앱 내부 호출로 같은 동작을 확인했어요). 설치판 업데이트 알림도 아직이에요.
- launch가 **스스로 새 세션을 만들어**(`setsid`) 띄운 프로그램은 앱이 정리하지 못해요(데모 launch에서는 해당 없음). 노드가 아주 많은 launch에서 10초가 모자라는 경우, 로봇 실기, 큰 bag 재생, bag 녹화를 터미널에서 멈춘 뒤의 파일 상태는 확인하지 못했어요.
- 다른 기기(Raspberry Pi 등)와 다른 ROS2 배포판(Humble 등).
