# JetDeck 6.0.0

> **플러그인 3단계** 업데이트예요. 팩이 앱 기능을 **권한으로 선언**해서 쓸 수 있어요: Device 폴더의 파일 보기·받기(`sftp.read`), 파일 올리기(`sftp.write`), Device 포트를 이 PC에 잠시 연결(터널, `tunnel`). 기기에는 아무것도 설치하지 않아요.

5.x를 쓰고 있다면 앱을 켤 때 **자동으로 받아서** 화면 위쪽에 알려 줘요. **다시 시작해서 업데이트**를 누르면 끝.

## ⚠ 보안 모델이 달라져요 — 꼭 읽어 주세요

5.6.0까지 팩은 **Device에서 명령만** 실행했고, 내 PC에는 아무 영향이 없었어요. 6.0.0부터 권한이 있는 팩은 다음을 할 수 있어요.

- **내 PC에 파일 저장** (받기) · **내 PC의 파일 읽기** (올리기) · **내 PC에 `127.0.0.1` 포트 열기** (터널)

지켜지는 것:

- 팩이 정한 폴더(`root`)·포트 **안에서만** 쓰여요. 앱이 쓸 때마다 경로를 다시 검사해요 (`..`·링크 탈출·시스템 폴더·열쇠·비밀처럼 보이는 파일 거부).
- **내 PC의 경로는 팩이 정하지 못해요.** 저장 위치와 올릴 파일은 시스템 대화상자에서 내가 골라요.
- 올리기와 터널은 **앱이 만든 확인 창**을 거쳐요. 권한은 저절로 실행되지 않아요 (자동 실행·그래프·배지에는 못 써요).
- 허용 창에 권한이 모두 보여요. 파일이 바뀌어 권한이 늘면 빨간 줄로 알려요. 공식 권한 팩도 켜기 전에 이 창을 거쳐요.

남는 것 (자세히: [권한 문서](https://github.com/Dawnilove/JetDeck/blob/main/docs/plugins/permissions.md)):

- **터널이 열려 있는 동안 이 PC의 다른 프로그램도 그 주소에 접속할 수 있어요.** 로그인이 있는 서비스에만 쓰고, 끝나면 닫아 주세요. 화면을 나가거나 새로고침하면 닫혀요.
- 거부 목록은 **이름 기반**이에요. 이름을 바꾼 비밀 파일은 막지 못해요. `root`를 좁게 쓴 팩만 설치하세요.
- 덮어써서 올리면 파일 권한이 `0644`로 바뀌어요.
- 새 버전이 같은 권한 이름으로 범위(폴더·포트)를 넓힐 수 있어요. 허용 창이 알려 주지만, 모음 목록에는 권한 종류만 보여요.
- "검토됨"은 안전 보증이 아니에요. 허용 창을 읽는 일은 그대로예요.

## ✨ 새 기능

- **권한 선언** — 팩 최상위 `permissions[]`와 `mode: "app"` 항목. `minApp` 6.0.0이 필요해요. 동작: `list`·`text`(글 파일 보기)·`get`·`put`·`open`.
- **허용 창 권한 구역** — 권한마다 종류·폴더 또는 포트·한도·위험도·쓰는 항목. 모음 설치 확인 창과 내용 보기에도 같은 구역이 있어요.
- **실행 화면** — 파일 표·글 보기, 받기·올리기 진행 막대와 취소, 터널 상태 줄(`127.0.0.1:포트`, 남은 시간, 정지 버튼).
- **공식 베타 팩 2개 (기본 꺼짐)** — `file-transfer`(Device의 `~/jetdeck-files` 폴더만), `web-tunnel`(Device 포트 8888·8000).
- **모음·심사** — 색인 `perms`를 빌드가 팩 파일에서 계산하고 `verify`가 비교해요. PR에 `Permissions` 절(20자 이상)이 필요하고, 권한은 팩당 3개까지예요. 심사 기준에 권한 항목이 늘었어요.
- **문서** — [권한](https://github.com/Dawnilove/JetDeck/blob/main/docs/plugins/permissions.md), [예제 팩](https://github.com/Dawnilove/JetDeck/blob/main/docs/plugins/examples/permissions.jdpack.json), JSON Schema 갱신.
- **호환** — 5.x 앱은 `minApp` 6.0.0 팩을 거부해요. 5.0~5.6 팩은 그대로 돌아요. 6.0.0에서 5.x로 되돌려도 설정이 깨지지 않아요.

## 보안 리뷰

별도 세션(Opus)이 구현을 읽고 재현해 봤어요. 결과는 **높음 0 · 중간 4 · 낮음 10**이에요. 중간 4개는 화면 작업 전에 고쳤어요. 낮음 10개는 코드로 고치거나 문서에 한계로 적었어요 (위 "남는 것"의 `0644`, 모음 목록 비교). 이 릴리스 작업에서는 낮음 항목을 하나씩 다시 재현해 확인하지는 않았어요.

## 확인한 범위

확인한 것:

- 자동 시험 504개, 타입 검사, 영어 사전 검사(사전 없음 0), 빌드 통과. 경로 이탈 글자 11종, 거부 목록, 토큰 변조, 한도, 터널 정리, 권한 증가 감지, 색인 `perms` 계산·비교, 공식 팩 2개·예제 팩 검증을 시험으로 고정했어요.
- 실제 앱(빌드본)과 실제 Jetson(**읽기 전용**): 공식 팩 2개가 기본 꺼짐으로 목록에 나오고, 켜기 전에 권한 구역(권한 2개·폴더·한도·쓰는 항목)이 있는 허용 창이 뜨는 것. 임시 외부 팩으로 `list` 실행, 터널 열기 → 이 PC `127.0.0.1` 포트 접속 성공 → 정지 후 포트 닫힘(접속 거부). 앞 단계에서 파일 표·글 읽기·확인 창 문장·터널 상태 줄·새로고침 뒤 터널 닫힘도 확인했어요.

**확인하지 못한 것**:

- **`get`(받기)·`put`(올리기)의 화면 흐름과 진짜 SFTP 쓰기**: 시스템 열기·저장 대화상자를 자동으로 누를 수 없었어요. 덮어쓰기 이름 바꾸기(OpenSSH 확장)도 실기에서 안 돌렸어요. 엔진은 가짜 Device 시험으로만 확인했어요.
- 공식 `file-transfer`·`web-tunnel`을 **켠 뒤 실제 실행** (Device에 `~/jetdeck-files` 폴더가 필요해요).
- 영어 화면, 밝은 테마·좁은 폭, 설치판 업데이트 알림, macOS.
- 브라우저의 로컬 포트 공격(DNS rebinding), 같은 PC의 다른 사용자, 백신·SmartScreen 반응, 저장한 파일의 Windows "인터넷에서 받음" 표시.
- 모음 색인에 새 공식 팩을 올리는 서명은 이 릴리스에 포함하지 않았어요.
