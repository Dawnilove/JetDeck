# JetDeck 5.0.0

> **플러그인** 업데이트예요. JSON 팩 파일에 명령·표시 방식·버튼·확인창을 적으면 화면에 기능이 생겨요. **내 PC에서 코드는 실행되지 않고**, 기기에는 여전히 아무것도 설치하지 않아요.

4.6.0 이하를 쓰고 있다면 앱을 켤 때 **자동으로 받아서** 화면 위쪽에 알려 줘요. **다시 시작해서 업데이트**를 누르면 끝.

## ✨ 새 기능

- **플러그인(팩)** — 환경 설정 → **플러그인 관리…** 에서 `*.jdpack.json` 팩을 설치해요. 팩을 켜기 전에 **허용 창**이 모든 명령 전문과 앱이 계산한 위험도를 보여 주고, 읽은 뒤 **허용하고 켜기**를 눌러야 켜져요. 파일이 한 글자라도 바뀌면 꺼지고 **다시 허용**을 물어요. 켜면 활동 막대에 **플러그인** 버튼이 생겨요.
- **앱이 위험도를 계산해요** — 읽기 전용임이 증명된 명령만 묻지 않고 실행돼요. 나머지는 확인창을 거치고, 팩이 위험도를 낮게 적어도 앱 계산이 우선이에요(⚠ 경고가 떠요). 확인창에는 앱이 계산한 이유가 먼저, 팩 작성자의 설명은 "팩이 쓴 설명" 상자로 따로 보여요.
- **공식 팩 3개(기본 켜짐)** — **기기 관리**(기존 기능 + 로그 보기 + 전원 모드 현재값), **ROS2 패키지·환경**(패키지·인터페이스 목록, 환경 요약, `ros2 doctor`), **모니터·성능**(클럭·팬·I2C·USB·GPIO, 젯슨에서만 보여요).
- **예제 팩(기본 꺼짐)** — 내 프로젝트·센서·학습 작업 템플릿. 복사해서 경로와 이름을 바꿔 쓰세요.
- **스니펫 → 팩으로 내보내기** — 스니펫 줄의 **팩으로 내보내기** 버튼이 스니펫을 팩 파일로 저장해요(스니펫 목록은 그대로).
- **터미널 입력 항목** — 팩이 열린 터미널에 명령을 입력해 줘요(읽기로 증명된 것만 바로, 나머지는 명령 전문 확인 후).
- **안전 모드** — 앱을 `--safe-mode`로 시작하면 내가 설치한 팩을 모두 읽지 않아요.
- 팩을 만드는 법은 [docs/plugins](https://github.com/Dawnilove/JetDeck/tree/main/docs/plugins)에 있어요(5분 튜토리얼, 형식 설명서, 보안, JSON Schema, 예제).

## ⚠ 바뀐 점 — 꼭 읽어 주세요

- **기기 관리 화면이 탭 1개에서 탭 4개로 바뀌었어요.** 4.5.0의 "업데이트·디스크·전원" 탭 하나(안에 구분 3칸)가 이제 **apt 업데이트 / 디스크 / 전원·부팅 / 로그 보기** 탭으로 나뉘어 기기 관리 묶음의 탭 줄에 들어가요. 위치(기기 관리 막대 버튼)와 동작(자동 읽기, 확인창, 미리보기, sudo 비밀번호는 새 터미널)은 같아요.
- **재부팅·종료 예약의 확인창이 위험(빨강)으로 올라갔어요.** 앱이 `shutdown`을 전원 명령으로 계산하기 때문이에요.
- 활동 막대의 **플러그인** 아이콘(콘센트 모양)은 외부 팩을 하나라도 켰을 때만 나타나요.
- `jetson_clocks --show`는 관리자 권한이 필요해서 모니터·성능 팩에서는 확인창과 sudo 흐름을 거쳐요.
- 읽기 허용 목록이 보수적이라 **너무 많이 물어보는 쪽**으로 실패해요. 필요한 읽기 명령이 막히면 [이슈](https://github.com/Dawnilove/JetDeck/issues)로 알려 주세요.
- 영어 화면과 실제 젯슨 전체 항목은 직접 눈으로 다 확인하지는 못했어요.

## ⬇ 내려받기

| 파일 | 용도 |
|---|---|
| `JetDeck-Setup-5.0.0.exe` | **Windows 설치판 (추천)** — 자동 업데이트 |
| `JetDeck-5.0.0-portable.exe` | Windows 설치 없이 실행 |
| `JetDeck-5.0.0-x86_64.AppImage` | Linux x64 (자동 업데이트) |
| `JetDeck-5.0.0-arm64.AppImage` | Linux arm64 (Jetson 등, 자동 업데이트) |
