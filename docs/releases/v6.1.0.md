# JetDeck 6.1.0

> **플러그인 3단계 이어서** 업데이트예요. 팩이 **이 PC의 시리얼 포트를 읽기만** 할 수 있어요(권한 `serial.read`). 장치로 아무것도 보내지 않아요. 기기에는 아무것도 설치하지 않아요.

5.x·6.0.0을 쓰고 있다면 앱을 켤 때 **자동으로 받아서** 화면 위쪽에 알려 줘요. **다시 시작해서 업데이트**를 누르면 끝.

## ⚠ 꼭 읽어 주세요 — 포트를 열면 장치가 다시 시작할 수 있어요

- **일부 장치(아두이노 등 많은 보드, 일부 USB-시리얼 변환기)는 포트를 열 때 다시 시작해요.** 앱은 열고 나서 제어선(DTR·RTS)을 낮추지만, 여는 순간의 변화는 앱이 막지 못해요(특히 Linux).
- **작업 중인 3D 프린터·CNC·PLC 같은 기계의 포트는 열지 마세요.** 모음은 이런 장치를 대상으로 하는 팩을 거부해요.
- 다른 프로그램이 같은 포트를 쓰고 있으면 열리지 않아요. 닫고 다시 실행하세요.
- 실행할 때마다 **내가 포트를 고르고**, 앱이 만든 확인 창(포트 이름·보율·한도·재시작 경고)을 거쳐요. 포트를 기억하거나 자동으로 고르지 않아요.

## ✨ 새 기능

- **`serial.read` 권한** — 팩이 보율(9600~921600 중 8개)과 한도를 선언해요. `minApp` 6.1.0이 필요해요. 항목은 `mode: "app"` + `op: "read"`.
- **읽기 전용 구조** — 포트를 여는 앱 코드에 쓰기 함수가 없어요. 흐름 제어는 끄고 8N1만 써요. 팩은 글자를 받지 못하고 화면에만 보여요(최근 2000줄, 비밀처럼 보이는 값은 가림).
- **한도** — 팩당 1개·앱 전체 2개, 기본 10분·5MB(최대 60분·20MB). 정지 버튼, 화면을 나갈 때, 연결이 끊길 때, 팩을 끄거나 바꿀 때, 앱을 닫을 때 포트가 닫혀요. SSH 연결이 있을 때만 써요.
- **허용 창·실행 화면** — 권한 구역에 시리얼(범위·보율·시간·크기·고정 안내), 실행 화면에 글자 구역·상태 줄·정지 버튼·끝난 이유·"데이터 없음" 안내.
- **공식 베타 팩 `uart-log` (기본 꺼짐)** — 115200 읽기. 켜기 전에 권한 구역이 있는 허용 창을 거쳐요.
- **모음·심사** — 색인 `perms`에 `serial.read:115200` 형식. 심사 기준에 시리얼 항목(기계 대상 팩 거부 등)이 늘었어요. [권한 문서](https://github.com/Dawnilove/JetDeck/blob/main/docs/plugins/permissions.md)와 [시리얼 예제 팩](https://github.com/Dawnilove/JetDeck/blob/main/docs/plugins/examples/serial.jdpack.json) 추가, JSON Schema 갱신.
- **호환** — 6.0.0 앱은 `minApp` 6.1.0 팩을 거부해요(팩 전체). 6.0.0 팩과 허용 기록은 그대로 유효해요.

## 같이 고친 것

- 6.0.0 보안 리뷰 #7: `open`(터널)·`put`(올리기) 확인 토큰에 팩 파일 지문을 넣었어요. 확인 뒤 팩이 바뀌면 거부돼요.

## 보안 리뷰

별도 세션(Opus)이 구현을 읽고 가짜 소스로 재현해 봤어요. 결과는 **높음 0 · 중간 4 · 낮음 7**이에요. 쓰기를 거치는 경로·토큰 위조·포트 닫기 누락은 찾지 못했어요. 중간 4개와 낮음 중 4개(#5~#8)는 고쳤고, 낮음 3개(#9~#11)는 후속으로 남았어요.

## 확인한 범위

확인한 것:

- 자동 시험 557개, 타입 검사, 영어 사전 검사, 빌드 통과. 가짜 포트로 열기 옵션(흐름 제어 끔·잠금·읽기 전용 객체), 한도, 줄 모으기·비밀 가림, 개수 제한, 정리, token 변조·재사용, 6.0.0 앱의 `minApp` 거부를 시험으로 고정했어요.
- 화면(임시 하네스, `window.api`를 가짜로 바꿔 `AppCard`만): 확인 창 4줄, 상태 줄, 데이터 없음 안내, 5000줄 입력 시 2000줄 유지, 정지와 끝난 이유.

**확인하지 못한 것**:

- **진짜 포트·실제 장치**. Windows·Linux에서 보드가 다시 시작하는지, 같은 포트를 PuTTY가 쓰면 거부되는지, 읽는 중 USB를 뽑아도 앱이 멀쩡한지는 릴리스 전에 사용자가 Arduino로 확인해야 해요(이 노트를 쓴 시점에는 미확인).
- OS 포트 고르기 창(버튼 8개·긴 이름), 허용 창 권한 구역, 실제 앱 안 팩 설치와 데이터 흐름, 영어 화면, 좁은 창, 화면을 나갈 때 정지, 앱 종료·렌더러 종료 때 정리(코드로만 확인).
- 블루투스 COM 포트, 낮은 RTS가 송신을 켜는 RS-485 변환기, 드라이버별 DTR 동작.
- 모음 색인에 `uart-log`를 올리는 서명은 이 릴리스에 포함하지 않았어요.
